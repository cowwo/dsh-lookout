# ADR 0001：文件行动作菜单用 DOM 注入

- 状态：已采纳（0.1.1）
- 日期：2026-10-20

## 背景

DSH 的文件面板由核心包 `@deepseek-ai/dsh-client-ui-sidebar-files` 提供。插件侧只拿到**面板级**的 slot（插槽），没有逐行 slot，也没有可扩展的行操作 API。而需求是：在每个文件 / 文件夹行的右侧提供一个「⋯」菜单，用来复制该行的绝对路径、下载单个文件。

## 决策

在插件内做 DOM 注入：

- 以 `[data-files-body]` 为根，按 `li[data-files-entry="file"|"directory"][data-files-path]` 定位行；`other` 行不碰。
- 行内已有 `button.row`，⋯ 作为它的**兄弟节点**插入（不能嵌套：嵌套 button 是非法 HTML，点击还会冒泡成「打开这个文件」）。
- ⋯ 绝对定位在行右上角；行 `li` 补 `position: relative`，行按钮加右内边距让位。所有改动都记下原值，退出时还原。
- 绝对路径**只从 `data-files-path` 读取**，绝不从行文本重拼（行文本可能是短名、可能被截断）。
- 用 MutationObserver + 200ms 去抖重扫；按钮自身就是幂等键，重复扫描不会重复注入。
- 连续 3 轮扫描一个按钮都放不进去就熔断：断开观察、只提示一次，提供「不再提示」；设置页另有总开关。

## 备选

1. **整块替换 tab body**：自己渲染文件树，能拿到逐行控制权。代价是要复刻宿主的排序、展开、拖拽、右键、键盘导航、刷新和选择状态，任一处不同步就会和宿主行为分叉；DSH 升级时同样会坏，且维护面更大。
2. **改 DSH 本体，新增逐行 slot / 行操作 API**：最干净。但插件无法自行发布，要等上游接受并随版本分发，短期不可行；而且会让插件依赖一个尚不存在的契约。

## 后果

- 正面：零宿主改动即可交付；宿主原生的展开、选择、拖拽行为原样保留；失效时只丢按钮，不会破坏文件树。
- 负面：依赖宿主 DOM 契约（`data-files-entry` / `data-files-path` / `button.row`）。DSH 升级换结构时菜单可能消失。已用「3 次熔断 + 一次性提示 + 设置开关」把影响限制在「功能不可见」。
- 能力边界：只支持单文件下载且 ≤ 20MB（超限由服务端 413 映射成提示）；文件夹下载置灰并标注「文件夹暂不支持」。
- 可观测性：注入失败只 `console.warn` 一次；熔断提示可点「不再提示」持久关闭。

## 现状与验收

- 实现位于 `client/client.js` 的 `//#region file row menu`（合并胶水层，不在三份逐字节锁定的原插件段内），入口 `rowMenuStart(ctx, require)`，由合并后的 `apply()` 首先调用。
- 离线验收：`test/row-menu.test.mjs` 覆盖注入、清理、菜单、复制、下载与错误映射、熔断 / 开关、健壮性、CSS token 审计；`npm test` 全绿。
- 人工验收：打开文件面板，文件 / 文件夹行右侧出现 ⋯；复制得到绝对路径；文件可下载，超 20MB 有提示，文件夹置灰；设置页关掉开关后按钮消失；宿主升级后若结构不匹配，最多看到一次提示，文件树仍可用。
