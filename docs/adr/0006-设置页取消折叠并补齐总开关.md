# ADR 0006：设置页取消折叠，并补上总开关

- 状态：已采纳（未发版）
- 日期：2026-10-30

## 背景

ADR 0005 之后，这一页第一次真的能读、能写。但「能读写」只解决了落地，没解决**眼睛怎么走**：一次编辑要上下跑，一个判断要来回看，最该有的入口干脆不在页面上。

**症状**

1. **改一个开关要往返约 1.3 屏才有保存按钮**。保存组在右上角，8 个事件开关在页面下半截；改完最后一个开关要往回滚 1.3 屏才按得到「保存」，改错一项再滚回去——一次编辑变成两次往返。
2. **端口与 3 类事件藏在两处折叠里**。「更多（端口/加密）」收着 SMTP 端口与加密方式；「还有 3 种情况（默认关）」收着 3 个低频事件开关。想确认「我这套配置到底会发什么」，得先展开两处；而展开状态不保存，下次打开又是收起的，等于每次都要重新找一遍。
3. **8 个事件全关时，判决条仍大字说「可以发信了」**。判定只问「收件人齐不齐、SMTP 齐不齐」，不问事件开不开。用户把 8 个开关全关掉（他要的就是清静），页面还在恭喜他「可以发信了」——一个自相矛盾的读数，比没有读数更糟。
4. **授权码粘贴后未保存，旁边仍显示「已保存」**。那句读数看的是「框里有没有值」，不是「值有没有写进去」：粘一段新授权码、不点保存，看起来就像已经生效。
5. **页面上根本没有「关掉通知」的入口**。后台从 ADR 0003 起就支持 `enabled === false` 时停发（`lib/notify/index.js` 三处提前返回），但这个开关从来没出现在界面上——想临时静音，只能逐个关事件，或者去改配置文件。

**量化（页面高度，700px 视口）**

| 状态 | 高度 | 折算 |
| --- | --- | --- |
| 干净态（两处折叠都收起） | 约 1199.5px | ≈1.7 屏 |
| 全展开 | 约 1646px | ≈2.35 屏 |

也就是说：默认的干净视图已经一屏半还多，而「要按的按钮」在最上面、「想改的东西」在中间和折叠里。问题不是写盘，是**布局把一次编辑拆成了几段**。

**两条路**

继续收（把低频项藏得更深）能让页面变短，但每加一层折叠就多一次「它到底在哪」的回忆成本，第 3、4、5 条症状一条也不会好转——它们都是「页面没说真话」或「页面缺入口」，跟长短无关。所以我们选另一条：**放平**，把常用项一次看全，把缺失的入口补上，同时让页面上每一句话都和实际行为对得上。

## 决定

### 1. 取消一切折叠

- 删掉「更多（端口/加密）」与「还有 3 种情况（默认关）」两处折叠，整页不再有收起态。
- 删掉事件开关旁的问号按钮，原先要点开才看的说明文字改为常显。
- 弹窗保留：恢复默认确认、授权码帮助。它们是「解释 + 确认」，不是「藏内容」，不需要点两次才看见。
- 折叠里的内容一件不删，只是全部常显。

### 2. 端口 / 加密 / 主机 / 用户名按四列栅格排

- 宽屏一行四列：主机、端口、加密、用户名。
- 窄屏两行两列，顺序不变。
- 端口与加密不再是「展开才能改」的字段，和其他字段一样随手可改；这四项本来就是一组（一个 SMTP 端点），排成一排正好读完。

### 3. 8 个事件开关排三列网格，不分组

- 8 个开关（7 个事件 + 子代理会话）按三列网格平铺，不分「常用 / 低频」两组——分组本身就是一种折叠，读者要先判断自己在哪一组。
- 说明压到 **≤16 字**并常显：

| 开关 | 说明（≤16 字） |
| --- | --- |
| 完成 | 跑完了，发一封 |
| 出错 | 出错和失败都发 |
| 阻塞 | 被阻塞时发一封 |
| 等你批准 | 要你点头才继续 |
| 你停止 | 你亲手停的才发 |
| 系统中断 | 重启热更算中断 |
| 触顶 | 回复太长被截断 |
| 子代理 | 子会话也算一份 |

### 4. 新增总开关「邮件通知」

- 这一条要说准：**后台一直都在**。`enabled === false` 时 `lib/notify/index.js` 有三处提前返回，插件只订阅、不动作、不发信——这是既有能力，本轮只是**补上界面入口**，不是新增后台能力。
- 关闭后 8 个事件开关全部变灰禁用、**但不隐藏**：看得见自己关掉了什么，也知道重新打开后哪些会恢复生效。
- 总开关是配置字段里的第一个开关，它管「发不发」，其余 8 个管「什么情况发」。

### 5. 页头吸顶，页底只放两个按钮

- 页头（标题与状态行）吸顶，滚动时始终在视口顶部。
- 页面底部的吸底条**只放「保存 / 放弃改动」**两个按钮，不重复状态行文字——状态在页头看，动作在页底按，各管一头，不打架。
- 「改完就能按保存」不再依赖滚动位置，这是症状 1 的直接解。

### 6. 判决条新增两档状态，并加一行人话摘要

- 新增两档，优先级自上而下：

| 优先级 | 状态 | 说什么 |
| --- | --- | --- |
| 1 | 总开关关闭 | 通知已关闭，不会发信 |
| 2 | 事件全关 | 8 个事件都关着，不会发信 |
| 3 | 其余（读不到配置 / 缺收件人 / 缺 SMTP / 可以发信等） | 原判定不变 |

- 新增一行「人话摘要」：用一句白话说明这套配置**实际会怎么工作**（例如「只在出错和等你批准时发，其余情况安静」），不复述字段名、不重复状态标题。
- 判定仍然只认**已保存**的配置（ADR 0005 的规矩不变），草稿不参与。

### 7. 区块改名

- 「收件人」不变；「怎么发」→ **发信方式**；「什么时候发给我」→ **通知时机**。
- 理由：前一个名字回答的是「用什么发」，后一个回答的是「什么情况下发」；原名口语化但含糊，「发给我」还会让人以为在配一个订阅。

### 8. 收件人改为单行输入框

- 多行文本域改单行输入框，一屏内高度可预期。
- 仍支持逗号 / 分号 / 换行分隔多个地址，解析规则不变；粘贴含换行的多地址文本依然可用。

### 9. 授权码脏态诚实化

- 粘贴了新授权码但还没保存时，读数改为「有未保存的授权码」。
- 保存成功后回到「已保存」；放弃改动随之回到「已保存」。
- 一句话原则：读数说的是**存没存**，不是**有没有值**。

### 10. 保存读数按秒数退化

- 60 秒内：「刚刚 / N 秒前」。
- 之后：「N 分钟前 / N 小时前 / N 天前」。
- 「已保存 · N 秒前」不再无限走字，长时间停留的页面也不会读出一个三位数的秒。

### 11. 「恢复全部默认」仍在页面最底部

- 位置不变：整页最后一行，离常用操作最远。
- 宿主没有弹窗原语时用浏览器 `confirm` 兜底，不再静默执行。

### 12. 6 处视觉对齐宿主

| 项 | 对齐值 |
| --- | --- |
| 说明文字字号 | 13px |
| 字段标签行高 | 20px |
| 卡片底色 | 补 `settings-card-fill` |
| 输入框底色 | 改 `bg-layer-1` |
| 卡片描边 | 用 `settings-card-stroke` |
| chips 字号 | 13px |

- 目的只有一个：这一页嵌在宿主设置界面里，不该看起来像另一个产品。

## 后果

- **正面（常用操作 ≤2 次点击）**：改开关 → 页底按保存；不用展开、不用回滚找按钮。
- **正面（无需展开）**：端口、加密、全部 8 个事件与说明一次看全，页面没有「藏着的东西」。
- **正面（判定不再自相矛盾）**：总开关关着、或事件全关时，判决条不会再恭喜你「可以发信了」；人话摘要让人不用翻译字段名也能知道结果。
- **正面（可就地验证）**：脏态、读数、判决条三处说的是同一件事（存没存、会不会发），发现不一致时能当场判断是哪一处错了。
- **负面（页面仍约 1.5 屏）**：不折叠必然换长度。这是主动接受的交换——用长度换「不用找」，并且把长度花在常显的说明上，而不是空白与折叠标题上。
- **负面（说明压短后，细节依赖帮助弹窗）**：≤16 字的说明只够说「什么情况下发」，说不清「aborted 只算你亲手停的」这类边界；这些细节移进帮助弹窗与术语表，页面上不再有第二份长解释。
- **负面（8 个开关常显）**：低频开关露在明面上，视觉噪声比折叠时高；换来的是「关掉通知」这类操作不必先找到折叠。
- **风险（肌肉记忆）**：老用户记得「更多」和「还有 3 种情况」在哪，改版后第一反应是找折叠标题；折叠消失不会给任何提示，只能靠自己发现东西已经摊开了。
- **风险（i18n 中英必须同步）**：改名、新增总开关、新增两档判定、新增人话摘要、授权码脏态文案，全都要中英两份一起改；只改一边会让另一种语言的页面继续说旧话。
- **风险（合并文件需重建）**：客户端是合并出来的单文件，改完源码必须重新生成；漏了重建，页面上看到的还是旧的折叠结构，而且看上去「改没生效」。
- **能力边界**：本轮只改界面，不改发信逻辑；总开关能停发，靠的是后台既有的 `enabled` 判断，不是这一页新做出来的行为。

## 被否决的方案

1. **保留折叠，只调样式（间距、字号、分组边框）**
   症状 1、2 一条也没解：保存按钮仍在 1.3 屏之外，端口和 3 类事件仍要展开才看得见，而且每次打开都回到收起态。「样式调好了会更顺眼」是真的，但顺眼不减少往返次数；更麻烦的是，调样式会让折叠看上去更像「推荐收起」，等于把「藏起来」这件事说得更理直气壮。故否决。

2. **分页或分 tab 承载高级项（基础 / 高级两个 tab）**
   这是把一处折叠换成一个更彻底的折叠：tab 背后的内容默认不可见，且切换 tab 会丢失「同一屏里对照」的能力——用户判断「我这套配置会不会发」，恰恰需要同时看到收件人、发信方式与通知时机。另外 tab 会引入新的状态（当前在哪个 tab、切走后草稿是否保留），而这一页的问题从来不是「内容太多分不下」，是「关键东西不在视线里」。故否决。

3. **删掉 3 个低频事件开关（你停止 / 系统中断 / 触顶）换长度**
   长度能省下三行，代价是这三个事件永远无法单独开关：要么被并进「出错」一起发（噪声变大），要么彻底不通知（信息丢失）。而「重启/热更算不算中断」「回复被截断要不要提醒」正是各人偏好差别最大的三项——删掉它们等于替用户拍板。省三行换掉三个真实选择，不划算。故否决。

4. **只做「全部关掉 8 个事件」的变通路径，不给总开关**
   后台早就有 `enabled === false` 的停发判断，界面上却没有入口，这种「能力在、入口不在」正是症状 5。用「把 8 个开关逐个关掉」当替代，等价于让用户用 8 次操作模拟 1 次，而且反悔时要记得原来哪几个是开的——恢复默认会把 SMTP 一起清掉。更糟的是它和判决条的语义打架：8 个全关时页面曾判「可以发信了」（症状 3），变通路径等于把这个矛盾固化成推荐做法。故否决。
